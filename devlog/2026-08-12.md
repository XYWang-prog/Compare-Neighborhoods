## 关键决策

1. **用 Places API (New) 的 searchText 而非 legacy textsearch**：用户的 key 未启用 legacy 版（REQUEST_DENIED），New 版 POST 接口实测成功且无需任何 Google Cloud 控制台操作
2. **CSV 真实字段代替"设施"**：firstmover 数据没有建筑名/设施，但用 sqft、免租月数、带家具、可入住时间等真实字段代替，徽章条件渲染（无数据不显示），坚持"不编造数据"原则
3. **构建时打包而非运行时拉取**：数据生成脚本手动运行，产出静态 TS 文件进项目，GitHub Pages 部署零后端依赖
4. **跨社区坐标匹配**：Places 建筑的房源常挂在相邻 CSV 社区名下（如 BLVD Collection 的房源在 "Waterfront" 而不是 "Newport"），用全局 0.01° 网格索引解决
5. **房源软过滤**：优先展示用户所选户型，无该户型时展示其他户型并明确标注，不做硬性隐藏

## 遇到的问题

1. **首轮只有 1/8 建筑匹配到房源**：三个原因叠加——(a) 中介黑名单误杀被 Google 标为 real_estate_agency 的真实楼盘（Avalon Cove）；(b) 只在同一 CSV 社区内找房源；(c) 纯距离匹配跨了曼哈顿街区（400 E 51st St 匹配到 401 E 50th St 的房源）。用白名单类型 + 全局网格 + 街道名验证 4 规则解决
2. **Avalon Cove 房源为 0**：其 CSV 行 building_type=UNKNOWN 被排除 → 从排除集移除 UNKNOWN（Places 已确认它是公寓楼）
3. **3 个区缓存路径报错 ENOENT**：fm_fulton/seaport 等区 id 含 `/` 创建了不存在的子目录 → 缓存文件名统一替换 `/`
4. **中介公司排名靠前**：Reside New York LLC（3640 评论）等经纪行按评论数排到最前 → 加公司后缀正则 + 黑名单 + 全通用词判定
5. **恶搞 POI 混入**：fm_upper_west_side 出现 "Jerry Seinfeld & Cosmo Kramer Apartment"（Google Maps 用户创建的玩笑地点）→ 加入黑名单重跑，已清除
